| D7 | 2026-08-19 | **`Arabic-lib` wraps the Farasa tools rather than porting them.** Inspection of `AdvancedHadith\Grammar` shows the Farasa suite is **Java** (NetBeans/Ant projects, serialized `.ser` models, mallet/weka/trove dependencies) — not JavaScript. The requirement is met with a pure-Python-facing library (`AdvancedHadith\Arabic-lib`) whose Farasa engines run the local JARs in a persistent JVM (JPype; pipe-server fallback), alongside native CAMeL Tools engines; one `annotate()` call evaluates all grammar layers simultaneously. **AMENDED BY D9**: wrapping is now the interim stage (P1) of a staged true Python port. | ARCH §12. Heavy annotation runs locally in batch; query-time NL2CYPHER frames use the pure-Python CAMeL subset. |
| D8 | 2026-08-19 | **AlKhalil2 adopted as the root-allocation engine; automated indexing pipeline added to `Arabic-lib`.** `Grammar\alkhalil_nlp` (already Python) excels at root allocation (تجذير) and joins the library as the authoritative `root` layer (cross-checked vs CAMeL), plus its proper-noun analyzer as a narrator-name signal. A new `arabiclib.indexing` pipeline converts flat page-stream editions (Shamela) into hadith-unit indexed content (headings→TOC tree, unit segmentation, number reconciliation, page anchors), **validated on dual-source books** (flat Shamela Bukhari scored against the native hadith.db index, ≥95% boundary F1 target) before indexing books that have no ground truth. Manual per-book runs via an `indexing_jobs` ledger with review UI. | ARCH §12.6–§12.7. Caveats: AlKhalil2 `resources/` lexicon must be obtained; GPT-converted code needs golden-test validation; live OpenAI key found in `alkhalil_nlp\.env` — rotate + gitignore. |

| D9 | 2026-08-19 | **Farasa true Python port approved (amends D7).** Per review, Farasa's quality must be preserved in Python: staged port — P1 JAR wrappers (immediate capability + permanent validation oracle), P2 one-time Java exporters dumping the `.ser` models to portable JSON/NPZ, P3 Python/NumPy reimplementation of inference only (no training code), P4 fidelity gate (≥99.5% token-level agreement with the JAR on a golden corpus) before a ported engine is promoted to primary. An **engine registry** assigns primary/fallback/cross-validate roles per layer so Farasa/CAMeL/AlKhalil validate one another. Port order: segmenter → POS → NER → diacritizer → dependency; constituency stays JAR-wrapped (neural indexer supersedes it for indexing). | ARCH §12.8. Promoted Python engines also become cloud-deployable (no JRE). |
| D10 | 2026-08-19 | **Two PyTorch neural models added (GPU-trained, incrementally fine-tuned).** (a) **Page-indexing model**: CAMeLBERT-CA + token-classification head (BIO labels for headings/hadith numbers/isnad/matn/commentary), trained from dual-source alignment (native hadith.db units ↔ flat Shamela pages) + rule-pipeline output + review-UI corrections stored in `training_examples`; sliding-window inference; confidence-driven review (active learning). (b) **Tashkeel model**: char-level Transformer (~25M params, benchmarked vs ByT5-small) trained on vocalized/stripped pairs from our own corpora; Farasa/AlKhalil/CAMeL as validation ensemble. Both: PyTorch 2.x + HuggingFace + PEFT/LoRA manual fine-tuning rounds, versioned checkpoints promoted only after beating the frozen dev set. Users are always served **processed content, never raw page dumps**. **Confirmed (user)**: GPU = local **NVIDIA RTX 3080, 12 GB**; the models are **local CLI accessory tools for content generation** (`arabiclib dataset/train/finetune/eval/promote/index/diacritize`) — Railway has no GPUs and the deployed application never invokes them; it serves precomputed outputs from Postgres. | ARCH §12.9, F16–F17. `index book --dry-run/--commit` converts a book into the indexed table ready for display. |

| D11 | 2026-08-19 | **Languages: `ar, en` only for now (~64 more later); hadith English translations are Kalimat.dev-first.** For each hadith, the Kalimat.dev API (`GET https://api.kalimat.dev/search`, header `X-Api-Key` from `KALIMAT_API_KEY`, `getText=2` + `indexes=[%22sunnah_lk%22]` — indexes omitted and `getText=1` for Qur'anic verses) is queried first; results accepted only with non-empty `en_text` **and** a normalized-similarity match of the returned Arabic against our matn; stored as `translation_source='kalimat'` with provenance (`kalimat_id`, `source_book`, `hadith_number`, `grade_en`), pre-marked authenticated. Fallback: `gemini-2.5-flash` (machine status). Responses cached by matn hash; manual batches per D4 unchanged. | ARCH §11.1, §11.6. Reference: Quran.chat `backend/tests/test_kalimat_api.py` + `docs/KALIMAT_API_DOCUMENTATION.md` (v1.1). |
